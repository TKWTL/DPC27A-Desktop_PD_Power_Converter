## 范围与规则

覆盖主菜单、设置、端口协议选项、休眠、显示参数、服务、关于、老化测试、游戏和 Statistics 模板。**Dashboard 主界面整体不参与 i18n**：`APP/Pages/dashboard.c` 内 `Dashboard_Page()`、`Dashboard_DrawStatusLine()` 及其所有辅助绘制/格式化逻辑，无论当前语言如何，均保留原英文/ASCII、数值格式、原固定宽度字体和布局；图标主菜单共用的顶栏状态行也不翻译。仅菜单入口 `-Dashboard` 仍可译为 `-仪表盘`（入口名称不属于仪表盘画面）。后续接入 i18n 时不得在通用绘制函数内无条件翻译所有字符串或全局替换 Dashboard 使用的字体。技术型号、协议缩写、数值单位维持英文/ASCII；不翻译调试串口、内部键、纯数字格式或装饰符号。协议选项的相同译文行用于审查，运行时可省略。

必须保留原始前导空格、横线和成对方括号；禁止 trim、改写英文键。动态格式模板需先查翻译再 snprintf，保留格式参数的数量、顺序、类型、宽度和精度。UI 当前已有底层 UTF-8 绘图和测宽接口，但尚未接入中文字体、翻译后的像素宽度、换行和菜单滚动适配；游戏固定坐标和统计栏亦需后续实测，表中的文本不是已验证的界面。当前不引入 Language 项（现有源代码没有该键）。

参考：IH01A-Compact_Induction_Heater 的 Firmware/APP/i18n.c 和 MiaoUI/I18N.md（原英文精确查找，显示层翻译，不改 menu ID）。

Statistics 采用独立定点数据项，翻译索引改为静态标签（含单位、PDO 模式）；右侧数值不参与翻译。温度标签为 Temp#1/Temp#2，不暴露芯片型号；Display/System 新增标签已加入清单，Dashboard 本身仍不翻译。

2026-11-15：用户提供的中文化前编译基线 text=54996 B、data=76 B，合计 55072 B；按链接脚本 FLASH=62 KiB，名义剩余 8416 B，未计可能独立于 size 统计的其他 Flash 段/对齐。仍只维护翻译规划，不启用运行时 i18n。

## IH01A 能力提取计划（2026-11-15；尚未实施）

对照 [IH01A 01933c4](https://github.com/TKWTL/IH01A-Compact_Induction_Heater/tree/01933c4be2d3cd08555319780679eecc2a0f9c17/Firmware/APP)：`i18n.c/.h`、`MiaoUI/display/dispDriver.c/.h`、`core/ui.c`、`widget/text.c` 及 `MiaoUI/I18N.md`。只提取能力和选框样式，不覆盖 DPC 的 MiaoUI 文件。

### 实施顺序

1. **Unicode 与字体**：DPC 已实现 `Disp_DrawUTF8()` / `Disp_GetUTF8Width()`，但 `Disp_DrawStr()` 仍使用 ASCII 路径；本地 `ThirdParty/u8g2/u8g2.h` 的 `U8G2_WITH_UNICODE` 默认行已注释，检查工程实际预处理定义并统一开启，Clean Build。用 Fusion Pixel 12px Proportional zh_Hans BDF、DPC 当前 97 汉字及 ASCII 32–126 重新生成 U8g2 子集；若未来增加 Language 标签，先更新字表再生成，不能直接拿 IH01A 的 89 字子集。保留 OFL 许可与生成命令，核对字形覆盖及 Flash。DPC 旧 `font_menu_main_h12w6` 保留，`UI_FONT` 不作全局替换。
2. **显示层翻译**：采用 IH01A 精确查找的思路，从当前 `i18n_table.inc` 实例化字典，英文原文键、前导空格、横线、方括号均不变，无匹配则原文返回。建议英文默认、RAM-only Language 开关（位置建议 System，需下一轮实施决定）；英文菜单继续旧字体，中文文本采用新子集。保留 `Disp_DrawStr()` 原 ASCII 语义，菜单标签显式 `Disp_DrawUTF8()` + `Disp_GetUTF8Width()`，不对整个底层调用自动翻译。
3. **TEXT 选框**：借鉴 IH01A 的 1px 左右留白、13px 高，基于实际动画基线定位。现 DPC 选框高11px、顶边 Y-9；目标试验英文顶边 Y-10、中文 Y-11，均高13px（行距13px），文字 X=原滚动 X+1，宽度 min(译文实际像素宽+2,84px)。统一用于 Calculate_Cursor、Draw_UI、Draw_TextPage 的目标宽及滚动边界；处理进/退页、切语言后重置横向滚动偏移与宽度；裁剪仍由本项目 title clip 控制，不移植 IH01A wideText 或 128×64 参数。垂直位置实测后微调。
4. **图标菜单**：DPC 保留 128×80 逻辑分辨率、30×30 图标、UI_IMAGE_Y=28、当前图标进度条/下划线/底标题位置。保留 `Dashboard_DrawStatusLine(ui)` 顶栏；它强制 ASCII 字体，绘制后显式选回当前菜单文字字体再测宽/画底标题。不能照搬 IH01A（128×64、图标 Y=13、无本项目顶栏）的 Draw_ImagePage。Dashboard 自绘页及顶栏一直使用原固定宽度字体。
5. **数据栏**：保留 UI_TITLE_X0..X1=0..84、UI_DATA_X0..X1=86..118、scrollbar=118..124。INT/FIXED 值及 --/OVF 继续用原等宽 ASCII 字体、6px 字宽、右对齐至 X1=118；UTF-8 只影响左侧标签，绘制标签前切回正确菜单字体。开关边框与填充保持最新 X=104/106（右边界116，距 scrollbar 2px）；保留现有 `UI_DATA_FIXED`、valid、RO、整数格式器，不用 IH01A 的左对齐数据渲染覆盖。
6. **其它文本**：Text_Widget 参照 IH01A 按完整 UTF-8 码点和实际像素宽度折行，保留 DPC 的 80px 高度、ASCII 换行及制表行为。参数弹窗标题同步翻译/测宽，数值仍定点。烧屏、游戏的固定坐标文案单独审查后再移植；游戏物理、图标、Dashboard 不做语言相关的几何变更。注意 UTF-8 不合法输入/截断、文字太宽的滚动边界及负坐标。
7. **验收与预算**：先 UTF-8/选框和单屏验证，再挂接语言表；双语均逐页核对 Settings/Display/System/Sleep/Statistics、端口、About、弹窗和返回动画。对比顶栏/整个 Dashboard 像素、数字右对齐、开关与 scrollbar 间隙。保持 UI 6ms、按键 8ms、软 I2C 事务间隙约束，无堆分配、无浮点。按同配置 Clean Build 比较 MAP/ELF；历史剩余8416 B只是名义预算，保留原 ASCII 字体后需计入完整新字库（IH01A 89汉字+95 ASCII 实测3428 B，仅作参照）、翻译字符串869 B、完整指针对照640 B及实际 Unicode/布局代码开销。新字体/语言切换的最终尺寸与字体渲染耗时尚未测量。
